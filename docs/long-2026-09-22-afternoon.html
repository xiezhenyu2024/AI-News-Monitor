【前言】
今天最值得关注的趋势是：智能体的竞争焦点正从"模型能力"转向"外围工程"——harness（智能体外壳：包裹冻结模型的提示词、控制流、工具、记忆与上下文管理）的蒸馏、正则化与自我进化成为学术与开源同时发力的方向。

【AI前沿】
1. 【ArXiv】智能体"外壳"成为独立研究对象，三篇论文同题共振
技术内容：Harness-Zero 提出"外壳蒸馏"——把针对特定领域/实例优化过的 harness 作为训练期指导，将其行为迁移进模型权重，使增益在单一固定目标 harness 下依然存活；RRSI 则指出 harness 的递归自我进化会记忆训练任务、在分布外基准上增益消失，因此引入正则化约束候选提案与选择；两篇均来自同一批作者群（Haoran Ye、Peng Xia 等）。
前提→做法→结论：前提是"最好的 harness 因领域、实例、模型而异"；做法是用优化 harness 做训练期引导、并对进化过程加正则；结论是 harness 增益可以被"内化"进权重，但必须防过拟合。
发展阶段：科研阶段
谁在干：学术团队（ArXiv cs.AI / cs.CL / cs.LG 三区交叉投稿）
基层体验：暂无
争议点：递归自我进化是否真能泛化，还是只是更精致的过拟合，尚无定论
重要程度：★★★★☆
时间标签：今日

2. 【ArXiv】多轮工具调用训练与评测补齐"诊断"环节
技术内容：Critical-State RL 指出多轮工具调用失败常系于单次模型调用，但奖励方差无法区分"当前动作差异"与"下游随机性"，于是用嵌套采样分离二者，只在可训练状态上做上下文赌博机优化；DolphinBench 则批评现有记忆基准是对话问答式、题目本身已暗示要检索什么，改为直接以智能体任务完成度评估记忆，每个 persona 约 50 万 token 历史、200 个任务。
发展阶段：科研阶段
谁在干：学术团队
基层体验：暂无
争议点：记忆基准从"准确率"转向"任务完成+成本/时间权衡"，可能让部分高分系统现形
重要程度：★★★★☆
时间标签：今日

3. 【ArXiv】多模态世界模型向"可交互、可触觉、可长时"推进
技术内容：WorldCrafter 让相机查询驱动隐式 3D 感知记忆，把多视角证据压缩进视频生成器有限的 token 预算，实现流式场景探索；DexTacWAM 把指尖触觉独立编码后注入视频扩散世界模型，在 22 自由度双臂平台六个接触密集任务上平均 70.6 分，最强基线仅 38.0；GameHorizon Suite 则提供首个大规模 AAA 游戏玩法数据集与多时间跨度评测。
发展阶段：科研阶段
谁在干：学术团队
基层体验：暂无

重要程度：★★★☆☆

【实战速报】
🛠️ 开发者用 Claude Code 插件 fast-jev-compaction 替换压缩摘要，保住逐字上下文
他不用 LLM 总结旧对话（摘要是有损的，文件路径、精确报错、约束条件可能丢失），而是让 Jev 在一次快速请求中对每个工具调用与结果打分，过期的直接删除或截断，保留的全部逐字保留，用户与助手文本顺序不变。也可作为 npm 库使用。
来源：GitHub Trending（tamaratran/fast-jev-compaction）

🛠️ 开发者把编码智能体搬离笔记本，在 AWS Lambda MicroVM 上搭云沙箱 Bivack
他为每个用户开一个 AWS Lambda MicroVM，配 Amazon S3 Files 上的持久 home 目录，可从浏览器终端或 VS Code workbench 接入。解决的问题是"不想在本地跑编码智能体"，实际体验是云端沙箱让智能体有了隔离且持久的执行环境。
来源：Dev.to（Gunnar Grosch）

🛠️ 开发者用 ChatGPT 网页版当"大脑"、Codex 当"手"，省下 API 额度
XiaoDuoYa 的 codex-with-chatgpt 把规划与 Review 交给已付费的 ChatGPT Plus/Pro 网页版，Codex 只负责执行，不用 API Key、不做逆向代理，走官方网页 + 只读 MCP 桥接。解决的痛点是"网页版额度闲置、Codex API 额度紧张"。
来源：GitHub Trending（XiaoDuoYa/codex-with-chatgpt）

【开发者讨论】
HN 上关于"AI 编程让 CI 成为瓶颈"的讨论出现明显分歧：Linear 官方博客称已重构 CI 流水线以跟上节奏，但评论区多位开发者认为真正的瓶颈不是 CI 而是人工测试与产品判断（aliclark："它能跑，但它真的做了我们想要的事吗？"）；dgroshev 更尖锐地指出 LLM 生成的大量测试只是内置行为和琐碎逻辑，"我们意识到业务逻辑里的样板代码，却远没意识到测试里的"。另有开发者 torben-friis 质疑：所有人都在狂奔，为什么产品反而没变好——新手机功能更少、Switch 2 仍未被破解、Windows 右键菜单要 3 秒。classictraffic 则补充 GitHub Actions 本身又慢又不稳，预计更多组织会迁往第三方 runner。
