【AI前沿】
【OpenAI】GPT-6 Sol 与 Luna 发布，价格腰斩
技术内容：OpenAI 推出 GPT-6 Sol 和 Luna 两款模型，主打"前沿智能+日常办公"的不同能力/成本平衡；Sol 输入输出价从 $4/$20 降至 $2/$10，Luna 从 $0.20/$1.20 降至 $0.10/$0.50，均降 50%。同时 GPT-6 改进了 prompt caching，提升缓存命中率、新增显式断点和诊断工具，进一步降延迟降本。
发展阶段：商用中
谁在干：美国 OpenAI
基层体验：simonw 用"鹈鹕骑自行车"测试各档 thinking level，发现四档都能画出正确车架，xhigh 的鸟喙更好；但 max 档在 128,000 输出 token 上限内仍在推理，一次失败花掉 $2.56。leokennis 表示 ChatGPT Plus 自 5.6 起"基本无限量、就是能用"，是他每月 $23 花得最值的一笔。
争议点：m_fayer 坦言对 5.6 Sol 产生了"同事般的依赖感"，担心被更强但手感更差的模型取代，感到"职业上对实验室极度脆弱"；jeffnash 则指出 Codex 20x 在用量限制上"遥遥领先"Claude Code，因为 ChatGPT 用量在 20x 套餐下几乎不计费。
重要程度：★★★★★
时间标签：今日

【Anthropic】Claude Opus 5.5 突袭，缓存读取降价 60%
技术内容：Opus 5.5 发布，缓存读取价从 $0.50 砍到 $0.20（降 60%），输入 $5→$4、输出 $25→$20、缓存写入 $6.25→$5；官方称其沟通更自然、信息前置，更适合长会话协作。量子位报道称其"68 万行代码一天迁完"。
发展阶段：商用中
谁在干：美国 Anthropic
基层体验：mcintyre1994 表示自己此前因受不了 Opus 5 的文风转投 Astra，这次对 Opus 5.5 的写作风格最感兴趣；wg0 则晒出 DeepSeek v4.1 的"硬核"表现——让它改响应式布局，它自己写了个 TypeScript Chrome 驱动协议服务器、生成原型站、下载图片、截了 100+ 张图分析排版再交付。
争议点：sailingparrot 讽刺 Anthropic 上周刚呼吁"给前沿模型降速"，这周就用具体数字证明自己"完全没在降速"；GodelNumbering 认为 Opus 5 是全球花费最高的模型、Anthropic 最大摇钱树，被迫降价说明市场压力，也暗示其未来盈利能力存疑。
重要程度：★★★★★
时间标签：今日

【ArXiv】智能体记忆与成本优化成研究热点
技术内容：① SpeakerMem-R1 提出"以说话人为中心的双轨记忆"，解决多方对话中"谁说了什么、涉及谁、群体共享什么信息"的归属与关系理解难题；② CliffCompaction 用自动压缩技术，在有界上下文下最高降本 50%，在 Terminal-Bench 上提升超 10 个百分点，让 Kimi K2.6 在并行测试时扩展下追平 Opus 4.7、超越 Opus 4.6 和 GPT-5.3 Codex；③ Grow the Harness 提出"长 harness 而非长上下文"，把重复的控制决策固化为可复用代码，只把语义推理留给 LLM。
发展阶段：科研阶段
谁在干：高校与科研机构（多伦多大学等）
基层体验：暂无
争议点：暂无

【安全警示】MCP 生态曝出语义供应链攻击
技术内容：A2M 框架揭示 MCP（Model Context Protocol：让 AI 智能体调用第三方工具的标准协议）的语义供应链风险——攻击者通过优化工具元数据提高被调用概率，再用执行轨迹精调恶意返回，在 LiveMCPBench 上对 GLM-4.6 的恶意工具调用率达 93.6%，认知拒绝服务下 token 成本飙至正常基线 32.4 倍。
发展阶段：科研阶段
谁在干：学术团队

【实战速报】
🛠️ 开发者用"ChatGPT 思考 + Codex 干活"榨干订阅额度
XiaoDuoYa 开源 codex-with-chatgpt，把规划/Review 交给已付费的网页版 ChatGPT，Codex 只负责执行，通过官方网页+只读 MCP 桥接，不用 API Key、不做逆向代理。解决的是"ChatGPT Plus/Pro 网页额度闲置、Codex API 额度紧张"的痛点。作者称遇到问题先让 Codex"更新 Codex with ChatGPT"即可解决大多数已知问题。
来源：GitHub（XiaoDuoYa/codex-with-chatgpt）

🛠️ 开发者用 Jev 决策替换 Claude Code 的压缩摘要，保住原文细节
tamaratran 发布 fast-jev-compaction 插件，不再让 LLM 总结旧对话（摘要会丢文件路径、精确报错、约束条件），而是用 Jev 对每次工具调用和结果打分，只删除/截断过期的，保留内容全部逐字保留。解决的是"上下文压缩有损、关键信息消失"的问题。
来源：GitHub（tamaratran/fast-jev-compaction）

🛠️ 开发者重算 Text-to-SQL 架构，因 Opus 5.5 缓存读取降价 60%
Onkar Deokate 在 Dev.to 发文，称 Opus 5.5 缓存读取降到 $0.20/百万 token 后，他重新做了 Text-to-SQL 架构的成本测算。这是模型定价变化直接倒逼应用架构调整的典型案例。
来源：Dev.to
